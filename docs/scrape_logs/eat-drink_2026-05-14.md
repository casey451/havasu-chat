## Notes

This run surfaced more drift than the runbook anticipated. Captured here as provenance.

**1. `places_load.py` was not category-scoped (fixed).** `enrichment_enriched.jsonl`
already carried 2,525 rows from a prior comprehensive *all-domain* scrape, and
`places_load` loaded the entire file (would have been ~2,266 providers across all
14 domains). Added a `--category` filter mirroring `places_discovery`'s
`DISCOVERY_CATEGORY_TO_DOMAINS` resolution — committed at `7455848`. The
pre-existing enrichment file is a head start, not pollution: it already holds
~280 enriched `lake_recreation` rows for Phase 5.2.

**2. Dead `relay/HAVA_BUSINESSES_...` doc reference (fixed).** Cleared from
`places_enrichment.py` and `places_categories.json` (`_about` blurb, plus a
now-stale "runner ignores domain" claim) — committed at `2d95962`. Mirrors the
§3.4.k fix already applied to `places_discovery.py`. Phase 5.0 close-out drift
finding 3 follow-on.

**3. §0 pre-flight gap — `alembic heads` vs DB state.** Pre-flight step 3 checked
`alembic heads` (the migration *files'* head) but not `alembic current` (the
*database's* actual revision). The local `data/events.db` was stamped
`1a2b3c4d5e6f` with an inconsistent schema. Recommend future per-category
runbooks check `alembic current` / run `alembic upgrade head` in pre-flight.

**4. Local `events.db` had an unmigratable inconsistent schema (rebuilt).** It was
stamped `1a2b3c4d5e6f` but had some later-migration columns (`sponsors.slot`) and
lacked others (`providers.category_id`) — the signature of a `create_all()`-built
DB (which only creates *missing* tables, never alters existing ones) that was
later stamped rather than migrated. `init_db()` in `app/db/database.py` has a
`has_events → command.stamp(head)` branch that produces exactly this. Operator
chose to rebuild clean: old DB backed up to `data/events.db.bak-20260514`, fresh
DB built via `alembic upgrade head` from base. The backup retains the prior
2,291 providers / 875 field_history / 5,578 chat_logs if ever needed.

**5. Load summary omits reconciler counts (open).** `places_load`'s
`--- load summary ---` prints input/skipped/inserted/updated but not
`reconcile_skipped_ambiguous` / `reconcile_merged_geo`, even though it tracks
them and the runbook §2 expects them surfaced. Cosmetic; a 2-line fix to the
summary print. Not yet done — flagged for a follow-up `scripts/` touch.

**Cost:** discovery ~84 Text Search requests (~$2.70 at ~$0.032/req); enrichment
~15 Place Details calls (~$0.60); well under the runbook's ~$5–9 + enrichment
estimate, because the prior scrape had already enriched 287/302 of the rows.
