## F. Missing surfaces (fresh-eyes pass) — build / don't build

**Build (all S-effort, template reuse, fit the "honest reference utility" ethos):**
1. `/outdoors` mode page — the desert half (SxS, hiking, fishing, golf) has no lens; 4th instance of the existing mode template. Cap modes at 4.
2. Seasonal heat-safety surface (`/summer`, June–Sept) — it was 108°F during the audit; cooling centers, indoor activities, early-lake-hours guidance. Safety-adjacent for a 65+ town.
3. 2-3 reference pages on the /gas pattern: launch ramps (fees/status/parking), downtown parking, RV dump stations. /lake currently deep-links "Launch Ramps" into *chat* — the demand is known, the answer is trapped behind a conversational UI.
4. `/events.ics` + RSS whole-calendar feed — serializer over existing JSON (~50 lines); footer link only, no UI. Snowbirds subscribe once in Outlook/Apple Calendar.
5. Print stylesheet for /events-ui (large type, no nav, QR back) — RV-park/senior-center corkboard distribution; it's CSS, not a feature.
6. Unified fatter footer across templates (may obviate a human-sitemap page).
7. `/accessibility` statement — but only AFTER the E3 a11y pass, so it doesn't overclaim.

**Don't build (agent + my concurrence):** multilingual/`/es`; neighborhood pages (already deferred); local news/roundup (a publication, not a feature — digest is the right-sized version); static itinerary pages (chat itinerary builder is the differentiated form); relocation guide; jobs/housing/volunteer boards; deals/coupons; `/weather` depth page; modes beyond 4. **Hold:** event-weekend hub pages — hand-build ONE for the next big weekend, measure search traffic, then decide.
