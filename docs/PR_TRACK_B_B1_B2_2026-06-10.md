## B1 — dedupe engine (WS-1)

The audit scripts already detected pairs well; what was missing was memory,
resolution paths, and the loop-closers. This commit adds exactly those:

- **`dedupe_resolutions` table + queue persistence.** The review queue at
  `/admin/providers/duplicates` computes candidates live, so before this a
  reviewed pair resurfaced on every page load. Resolutions
  (`not_duplicate` / `multi_location` / `parent_child` / `merged`) persist per
  unordered pair (`pair_key`), with the audit signal snapshotted in `reason`
  (labeled examples, §5.3 spirit). Queue + dashboard card count filter
  resolved pairs out.
- **Resolution paths the audit demands (§3 shapes).** *Multi-location*: both
  rows stamped with a shared `Provider.location_group_id` — kept, never
  merged; profiles cross-link "Other locations" with street-line labels.
  *Parent org/departments* (Specialty Associates shape):
  `Provider.parent_provider_id`; the parent profile renders a
  "Departments & services here" strip, children link up via "Part of".
  T2 (182 phone-exact groups) is deliberately a human queue — these are the
  legitimate shapes mixed with true dupes.
- **Merge primitive hardening** (`app.contrib.provider_merge`): stamps
  `attributes.merged_into_slug` so retired slugs 301 (was batch-script-only;
  the UI path used to 404 old links) · `google_place_id` gap-fill is now a
  MOVE (clear-flush-set) — a copy violated the `ux_providers_google_place_id`
  partial unique index, which spans retired rows · department children of a
  merged-away parent repoint to the keeper · every merge records a `merged`
  resolution.
- **Ingest gate.** `reconcile_hit` place_id tier now also matches
  `Provider.google_place_id`, not just `Location.google_place_id` — closing
  the legacy-row gap where a re-ingest could fall through to geo/name tiers
  and crash on the unique index (or duplicate). T1 backlog = 0 in prod
  confirms the index holds; the gate keeps it that way at reconcile level.
- **Batch tier:** `scripts/merge_place_id_duplicates.py` consumes only the
  audit's `auto_merge_eligible` (place_id) tier. Dry-run default (keep/drop,
  reason, field-diff, repoint counts) → `--apply --confirm` → JSON rollback
  snapshot → one transaction. Skips human-resolved/linked pairs. Today it's
  future-proofing (0 eligible pairs).

## B2 — WS-2 Bayesian ranking + WS-4 address quality

### WS-2 (C = 25, justification)

`app/core/rating_prior.py`: `score = (R·n + m·C)/(n + C)` with **C = 25** and
`m` computed live (review-weighted mean, 6h TTL cache, 4.47 measured-prod
fallback). Calibration on the 2026-06-10 prod export (1,910 rated providers,
median 25 reviews): C=10/25/50 leave the top-20 identical to the raw sort
(zero thin <10-review entries surface); C=100 reshuffles the head (13/20
overlap). 25 is the spec's low end and the natural prior ≈ median review
count: maximal thin-tail correction, zero head churn.

Replaces the rating term at all four sort sites (home eat row, category
browse + facets, leaf pages, trades, dept peek) and **retires the hard
`MIN_RATING_REVIEWS` qualified tier** — the prior does the same job
continuously (a 2-review 5.0 shrinks to ≈m and can't top a leaf), without
bucket cliffs. `MIN_RATING_REVIEWS` still gates rating *display* on cards.
The liveness dampener multiplies the shrunk score exactly as it multiplied
the raw rating. FAQ/leaf-intro copy already promised "volume-weighted
rating … strong rating across many reviews ranks above a perfect score from
only a couple" — the code now does what the copy says (no copy change
needed; that's the WS-2 "FAQ updated to match" in reverse).

### WS-4 (structured components, never concatenate)

- **Writer fix:** `pdga_courses`/`usapickleball` `format_address` now
  pre-strip an existing Lake-Havasu-shaped suffix from the street
  (`street_line` is a no-op for other cities) — the doubling mechanism dies
  at the source.
- **Helpers** (`app/core/address.py`): `normalize_full_address` (collapse
  repeated suffixes to one canonical `street, Lake Havasu City, AZ [zip]`,
  refusing anything needing judgment) and `parse_zip` (864xx-prefixed, so
  5-digit street numbers never false-positive).
- **Mechanical fix script** `scripts/fix_address_quality.py`: city-repeat
  collapse (prod sizing: 377) + zip text-backfill (subset of the 976 whose
  text carries a zip) + comma/space runs, on Location AND mirrored Provider
  columns. Dry-run → counts → Casey approves → `--apply --confirm` with JSON
  snapshot, one transaction. Lat/lng-based zip backfill (external API) is a
  separate pass, out of scope.
- **Flag queue** (the 812 no-street-number rows — many legit): live-computed
  portal page `/admin/portal/addresses` + dashboard card; "Mark OK" persists
  via `Provider.attributes["address_flag_dismissed"]` (audited). Review,
  never auto-fix.
