{# Direction C Service icon grid -- 6-up icon tiles (2 rows on desktop, 4 rows of 3 on mobile). Renders inside ``home_c.html``. Expects ``service_cards`` in context: a list of dicts from ``app.home.queries_c.services_grid()``. Per card (defaults guaranteed by services_grid): name display label (e.g. "Home & property") route URL slug for D5 /categories/{route}; also drives the tile count via CATEGORY_FILTERS[route] (single source of truth for which legacy Provider.category slugs the tile counts and the destination page filters by). svg_path inline SVG string count int when > 0, None otherwise count_label "N listed" or "" (never "0 listed") href "/categories/{route}" Grid mechanics live in ``home_c.css``: .c-svc-grid repeat(6, 1fr) desktop, repeat(3, 1fr) <= 720px .c-svc tile (icon + name + optional count) .c-svc-ic 24x24 SVG container, accent stroke .c-svc-nm name (Inter 14px) .c-svc-ct count line ("38 listed"), Inter 12px / ink-3, rendered only when ``card.count_label`` non-empty. Tiles always render (icon + name + tap target). Count line hides when count is 0 -- BUILD.md "no zero counts" rule. A tile pointing at a route that doesn't exist yet (pre-D5) still taps -- the route will 404 cleanly with the existing FastAPI default. Empty-state: the parent template gates this include with ``{% if service_cards %}`` -- defensive only. ``services_grid()`` always returns 12 cards; an empty list would mean the function was monkey-patched or the import failed. #}
